# Разбор оригинала субагентом (фаза 1)

Разбор оригинала — самая «тяжёлая» по контексту фаза: тексты страниц, выгрузки ссылок и
товаров, снимки DOM, скриншоты по 10–20k токенов каждый. В основной сессии они остаются в
контексте до конца и перечитываются на каждом шаге. Поэтому фазу 1 делает субагент: он
пишет результат в файлы и возвращает короткую сводку, а основная сессия читает только `brief.md`.

## Запуск

`Agent` с `subagent_type: "general-purpose"`, в фоне не нужно (следующий шаг зависит от
результата). Промпт — шаблон ниже с подставленными `<url>` и `<slug>`. Если пользователь
приложил сведения (логотип, страницу контактов, пожелания) — допиши их в промпт.

```
Разбери сайт <url> для концепта редизайна <slug>. Ничего не верстай и не коммить.
Репозиторий: /Users/iliyaandrushov/WebstormProjects/webdozerz.github.io.
Перед работой прочитай .claude/skills/redesign-concept/references/function-inventory.md
(скрипт сбора функций и чек-лист) и раздел «Куда отправлять» в
.claude/skills/redesign-concept/references/outreach.md.

Браузер: chrome-devtools; если занят — встроенный браузер (mcp__Claude_Browser__*).
Открой десктоп и 390 px. Пройди все типы страниц: главная, каталог/категория, карточка,
корзина/заявка, доставка/оплата, контакты, о компании. Нажми всё, что раскрывается:
«Каталог», бургер, фильтры, мини-корзину, вкладки товара, наведение на меню.
Ленты с подгрузкой докручивай до конца (у Taplink крутится контейнер, а не window) и
пересчитай ассортимент.
Разбирай только сайт. Telegram, VK, MAX, карты и другие внешние страницы компании не
открывай: ссылки на них запиши из контактов сайта как есть.

Запиши в .redesign/<slug>/:
1. data.json — реальные данные, ничего не выдумывай:
   { "products": [{ "name", "price", "oldPrice", "unit", "stock", "category", "img", "url", "variants" }],
     "categories": [{ "name", "count", "img" }],
     "delivery": [...], "payment": [...], "announcements": [...],
     "contacts": { "phones", "emails", "address", "hours", "messengers", "social" } }
   Все товары, если их до ~300; больше — по 10–20 из каждого раздела и общее число.
2. brief.md, не длиннее ~120 строк, по разделам:
   - Бизнес: что продаёт, кому, город и часовой пояс, платформа (как определил)
   - Бренд: логотип (URL, есть ли прозрачность), цвета (hex самых частых фонов, текста,
     кнопок через getComputedStyle), шрифты, тон текстов, свои графические элементы
     (иконки разделов, вывеска, упаковка) с URL
   - Страницы: список с URL
   - Инвентарь функций: таблица «функция → где → как работает», отдельно скрытые
     (по клику/наведению) и что обычно теряют по чек-листу
   - Условия: доставка, минимальный заказ, оплата, сроки — цитатами с сайта
   - Каналы связи: 2–3 по приоритету из outreach.md с причиной; сотрудник, названный
     ответственным за сайт/магазин, — первым
   - Наблюдения для письма: 3–5 конкретных проблем, которые владелец сам может проверить
     (с URL), и перепутанные фото товаров, если нашёл
   - Сильные приёмы оригинала, которые стоит сохранить
3. Скриншоты для себя не сохраняй в репозиторий; og не нужен.

В ответ верни 10–15 строк: число товаров и разделов, платформу, 3 главные находки,
пути к файлам. Не пересказывай brief.md целиком.
```

## После возврата

- Прочитай `.redesign/<slug>/brief.md` целиком — это вход для брифа (фаза 3) и письма (фаза 7).
- `data.json` целиком в контекст не читай: посмотри структуру
  (`node -e` с `Object.keys` и первыми 2 товарами) и преобразуй скриптом в `utils/<slug>.ts`.
- Не хватает детали (как выглядит конкретный блок) — открой эту одну страницу сам или
  спроси того же субагента через `SendMessage`, а не переделывай разбор.
- Папка `.redesign/` в `.gitignore`: это рабочие материалы, они переживают сессию и нужны
  при правках концепта и письме через неделю.
