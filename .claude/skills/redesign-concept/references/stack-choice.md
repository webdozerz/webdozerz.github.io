# Статичный HTML или Vue/Nuxt

Выбор определяется тем, **что ты потом продаёшь клиенту**, а не удобством вёрстки.

## Статичный HTML (`public/redesign/<slug>/`)

Выбирай, когда:
- оригинал на CMS, которую оставляем (WordPress/WooCommerce, Tilda, Битрикс, InSales),
  и предложение — «обновим оформление, админка и заказы останутся»;
- нужно 4–6 типов страниц, данные можно продублировать в разметке;
- концепт должен открываться мгновенно и без сборки.

Почему: статичная вёрстка близка к тому, что реально делается темой и CSS поверх CMS.
Если в макете будет SPA-магия, которую тема не повторит, письмо станет нечестным.

Как устроено: несколько `.html` с общими `assets/styles.css` и `assets/app.js` (ванильный
JS без сборки, IIFE). Повторяющиеся блоки (шапка, подвал, таббар, модалка входа)
дублируются в каждом файле — правь их скриптом по всем страницам сразу (Python/sed),
а не вручную, иначе страницы разъедутся.

Пример: `sttorg70` (WooCommerce на теме XStore).

## Vue/Nuxt (`pages/redesign/<slug>/`)

Выбирай, когда:
- у оригинала нет полноценной CMS (Taplink, конструктор-визитка, страница в соцсети),
  и предложение — новый сайт;
- нужна сквозная логика: корзина между страницами, фильтры и карточки из одного массива
  данных, динамические маршруты `product/[id]`;
- товаров/услуг много и дублировать разметку бессмысленно.

Как устроено: родительская страница-оболочка `pages/redesign/<slug>.vue` с `<NuxtPage />`,
дочерние страницы, компоненты в `components/redesign/<slug>/`, данные в `utils/<slug>.ts`,
состояние в `composables/use<Slug>Cart.ts` (useState + localStorage).

Пример: `foodgood` (Taplink → новый магазин).

## Пограничные случаи

| Ситуация | Решение |
|---|---|
| WooCommerce, но клиент жалуется на скорость и хочет «новый сайт» | Сначала HTML-концепт оформления; новый фронтенд — отдельное предложение |
| Tilda-лендинг одной страницей | HTML, одна-две страницы |
| Каталог 200+ позиций на конструкторе | Vue с данными в массиве, 15–30 реальных позиций |
| Нужно только показать главную | HTML |

Решение и причину запиши в бриф и в карточку каталога (теги `HTML/CSS` или `Nuxt 3`).
