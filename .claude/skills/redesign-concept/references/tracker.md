# Трекер лидов

Список сайтов и воронка «концепт → письмо → ответ → договор» живут в артефакте
**«Редизайн-лиды»**: https://claude.ai/artifact/LEwiDXTP1gqtPoPv5YrxSp

Страница рисует строки из своей базы, поэтому трекер обновляется записью в базу
(`ArtifactData`), а не перепубликацией страницы. Пользователь хочет, чтобы трекер
обновлялся сам по ходу скилла: не жди просьбы и не откладывай на конец разговора.

## Схема

Коллекция `sites`, один документ на компанию. `doc_id` — латиница, обычно slug концепта
(`sibprod`, `tomich`); у лидов без концепта — короткое имя домена (`style-product`).

| Поле | Что это |
|---|---|
| `name` | название как у компании: «ТД «Томич»», «Сибирский продукт» |
| `url` | адрес сайта, который делаем, с `https://` и `/` на конце |
| `city` | город |
| `niche` | группа на странице: `Продукты и опт`, `Фермерские продукты`, `Цветы и кондитерские` или новая |
| `platform` | движок оригинала: `1С-Битрикс`, `Wix`, `Setup.ru`, `самописный PHP` |
| `fit` | оценка лида 1–5 |
| `order` | порядок внутри ниши |
| `why` | 1–2 предложения: что не так с сайтом, проверяемые факты (их же берут в письмо) |
| `check` | `true` — «проверить активность» (сайт или компания могут быть заброшены) |
| `contact` | почта / мессенджер / телефон для письма, показывается под `why` |
| `top` | `true` — бейдж «лучший кандидат», такие строки идут первыми; после галочки «Концепт» бейдж пропадает сам |
| `topWhy` | почему лучший — подсказка при наведении на бейдж |
| `concept` | ссылка на концепт `https://andryushov.me/redesign/<slug>/` |
| `steps` | `{concept, sent, replied, deal, declined}` — галочки воронки |
| `work` | `true` — «Взять в работу»: кнопка на странице копирует `/redesign-concept <url>` для новой сессии и ставит отметку; без концепта (`steps.concept`) кнопка видна, с концептом — нет |

## Когда писать

1. **Фаза 1, начало.** Найди строку компании: `query` по `url`, если не нашлась — `list`
   и сверка по `name` и домену (у компании бывает несколько сайтов). Если адрес в трекере
   другой, чем тот, что делаем, исправь `url`. Так было со «Стиль Продукт»: в трекере
   стоял шаблонный style-product.ru, а рабочий сайт — rybasibiri.ru на Wix. Обнови
   `platform`, `why` (по разбору оригинала) и сними `check`, если сайт живой.
   Строки нет — создай её со всеми полями, кроме `concept` и `steps`.
   Поставь `work: true` — концепт по этому сайту начат.
2. **Фаза 6, после проверки живой страницы.** `concept` = ссылка на концепт,
   `steps.concept = true`. Ссылку ставь только после того, как `curl` вернул 200.
3. **Фаза 7, когда пользователь сказал, что отправил письмо.** `steps.sent = true`.
   Не ставь заранее: письмо отдаётся пользователю, а отправляет он сам.
4. **Ответ, договор, отказ** — по словам пользователя: `replied`, `deal`, `declined`.
5. **Удаление** — пользователь удаляет строку кнопкой «Удалить» на странице или просит тебя
   (`delete` с `if_version`). Не удаляй сам, если не просили.
6. **Новые лиды** из поиска компаний — новыми документами, по одной строке на компанию,
   одним `batch`.

## Как писать

- `update`, а не `set`: так сохраняются поля, которые трогать не нужно.
- Перед записью прочитай документ и передай его `version` как `if_version`. Если запись
  отклонена из-за версии, перечитай и повтори, не затирая чужие изменения.
- `steps` — объект целиком: `update` заменяет его, поэтому передавай все уже отмеченные
  этапы (`{"concept": true, "sent": true}`), иначе снимешь галочки.
- Несколько строк — одним `batch`.
- После записи скажи пользователю одной строкой, что изменилось в трекере.
