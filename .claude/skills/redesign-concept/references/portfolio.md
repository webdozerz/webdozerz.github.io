# Реестр облика концептов

Концепты живут рядом в каталоге `/redesign/`, и их видит каждый, кто откроет одну
ссылку из письма. Если два магазина из одной ниши выглядят как один шаблон с другим
логотипом, это читается как «штампует под копирку», и ценность бесплатного концепта
падает. Поэтому каждый новый концепт сверяется с этим реестром ДО брифа и вносится в
него ПОСЛЕ публикации.

Структура ниши (какие блоки есть, какие функции) может повторяться. Облик (оси ниже)
не повторяется.

## Оси облика

| Ось | Что это | Варианты — в `layouts.md` |
|---|---|---|
| Палитра | акцент + тёмный + поверхность | от бренда и ниши |
| Шрифт | гарнитура заголовков и текста | `visual-direction.md`, раздел «Шрифты» |
| Шапка | H1–H5 | `layouts.md` |
| Первый экран | A–G | `layouts.md` |
| Карточка товара | K1–K5 | `layouts.md` |
| Форма | радиусы и характер углов | острые 2–4 / мягкие 8–12 / круглые 16–24 |
| Мобильная навигация | M1–M4 | `layouts.md` |
| Фирменная деталь | одна вещь, которая есть только у этого концепта | — |

**Правило отличия.** Новый концепт отличается от КАЖДОГО концепта той же ниши минимум
по пяти осям из восьми и от любого концепта вообще минимум по трём. Шрифт и первый
экран не повторяются у двух концептов подряд, даже из разных ниш.

## Как вносить новый концепт

После публикации добавь раздел по образцу: slug, ниша, город, стек; затем по строке на
каждую ось. Если какая-то ось совпала с другим концептом, пометь «ПОВТОР» и почему это
было оправдано (например, клиент сам попросил свой цвет).
